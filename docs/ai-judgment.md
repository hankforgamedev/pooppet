# AI 判讀 —— 真的接上去的那一版

Spec B 說判讀是假的。這個 repo 兩種都有：

- **預設：demo 模式**（假的，隨機 + ⚙ 手動指定）—— 現場零意外，Spec B 承諾不變
- **可選：真判讀**（⚙ → 判讀來源 → 開）—— 打 `POST /api/judge`，真的送圖給 VLM

開關存在 localStorage，開一次就記住。`file://` 直接開檔案時一律 demo 模式。

## 判讀範圍就是 Spec A 寫的那麼窄

模型只回四個欄位：

| 欄位 | 值 | 用途 |
|---|---|---|
| `is_stool` | boolean | 不是便便就不記帳 |
| `bristol` | `none` / `1`–`7` | 決定石化／完美／液化 |
| `oily` | boolean | 決定油亮 |
| `confidence` | `low`／`medium`／`high` | 目前只記錄，還沒拿來調行為 |
| `note` | ≤25 字繁中 | 卡片上那句雞講的話 |

system prompt 裡明文禁止：**顏色、血、黑便、黏液、寄生蟲、疾病名稱、健康建議、診斷**。
輸出用 structured output（JSON schema）鎖死，模型沒有欄位可以塞這些東西。

辣不在裡面 —— **辣是用戶自填**（右上角 🌶），不是 AI 判的。Spec A 就是這樣寫的，
而且辣本來就看不出來。

## 訊號 → 變形

```text
bristol 1,2  → stone    石化
bristol 4    → perfect  完美
bristol 6,7  → watery   液化
oily=true    → oily     油亮
🌶 自填      → spicy    噴火
bristol 3,5  → （沒有訊號，還行）
```

一次餵食可以同時產生多個訊號（例如 oily + perfect）。

## 累積制

`最近 3 次餵食中 ≥2 次同訊號 → 變形`

- 沒達標：只給**一秒的即時表情反應**（粒子 + badge 閃一下），然後退回累積進度（`石化 1/2`）
- 達標：變形、發光、放粒子、出判讀卡
- 三次裡沒有任何訊號達標：**解除**，變回正常 —— 這是回訪的獎勵時刻
- 兩個訊號同時達標時的優先序：`stone > watery > oily > spicy > perfect`（問題訊號先演）

歷史存 localStorage（`pooppet.hist.v1`），只留最近 3 筆，關掉 app 再開還在。

⚙ 手動指定**一次就生效**，不等累積，而且完全不打 API。

## 判讀失敗怎麼辦

雞不會卡住。任何一種失敗（沒 key、連不上、逾時 25 秒、模型拒答、回傳解析不出來）
都會退回隨機，判讀卡的小字會寫「判讀連不上（`code`）」。

demo 現場網路爛掉不會開天窗，但也不會假裝判讀成功。

## 圖片與隱私

- 前端先把照片縮到 **1024px JPEG q0.82** 才送（手機原圖 8MB 會打爆 request body）
- `api/judge.ts` **不寫任何持久化儲存**：圖片進來、判讀、丟掉
- 原圖不離開手機，只有縮圖送出去判讀

Spec A 的隱私架構（貼圖遮罩、刪帳號＝真的刪圖）是有帳號之後的事，這輪還沒有帳號。

## 換模型 / 成本

`POOPPET_MODEL` 環境變數，預設 `gpt-4o`。要壓成本就換成便宜的 vision 模型。

## 沒有驗證過的部分

判讀的**準確度完全沒有驗證過** —— 沒有標註資料集，沒有測過真實照片。

程式路徑是通的（輸入驗證、錯誤對應、退路、累積制都有測試蓋到），但
「模型判 Bristol 準不準」這件事是 Spec A 說的那句話：真正的成本是準確度驗證，不是技術。
那件事還沒開始做。
