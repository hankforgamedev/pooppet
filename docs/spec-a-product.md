# Spec A — 完整版（產品方向）

> 這份是「給他看的方向」，不是這輪要做完的東西。這輪要跑的是 [Spec B](./spec-b-demo.md)。

## 產品定位

好笑優先的排泄物電子雞。健康資訊是佐料，不是賣點。

明確定位在 **wellness／娛樂**，不觸碰醫材法規。

## 核心迴圈

```text
上廁所 → 拍照餵雞 → 雞當場反應 → 依累積訊號變形 → 想解除變形所以在意飲食 → 明天再來
```

## 判讀範圍（刻意收窄）

只判 **Bristol 1–7** + **油亮／浮**。

**不做顏色偵測、不做黑便警示。**

判錯的最壞後果是動畫演錯，沒有人受傷。黑便／血便靠 onboarding 一次性衛教 ＋
設定裡的常駐靜態頁面處理 —— 沒有偵測功能，就沒有漏判責任。

這條是產品的地基，不是可以之後再補的細節。任何「順便偵測一下顏色」的提案都會
把這個 app 推進醫材的射程內，一律拒絕。

## 五種變形（累積制）

最近 3 次餵食中 **≥2 次同訊號**才觸發變形；單次只有一秒的即時表情反應。

這讓 AI 判錯有容錯空間，也製造「連續石化三天終於解除」的回訪動機。

| 訊號 | 型態 | 依據 |
|---|---|---|
| Bristol 1–2 | 石化（灰、卡頓） | 硬顆粒＝水分纖維不足 |
| 油亮／浮 | 油亮（反光、滑倒） | 油亮會浮特別臭＝脂肪過多 |
| 辣（用戶自填） | 噴火（冒煙、抖） | 辣不改變顏色，但加速蠕動 |
| Bristol 4 | 完美（發光、煙火） | 臨床理想型 |
| Bristol 6–7 | 液化（融成一灘） | 通過太快 |

Bristol 3 與 5 不對應任何變形 —— 它們是「還行」，不需要演出。

## 社交（分階段）

- **v1** 純私人
- **v1.5** 可看朋友的雞和排行榜
- **v2** 才做 PicPet 式共養

## 隱私（架構決策，不可事後補）

- 預設全私密。
- 分享出去的圖一律強制套寵物貼圖遮罩，原圖只有本人看得到。
- 刪帳號＝真的刪圖。

這是唯一能讓人願意上傳的前提。事後補的隱私沒有人會信。
